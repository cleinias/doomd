* The screen while debugging

#+begin_example
┌─────────────────────────────────┬────────┐
│ ●  41  def step(x):             │ Claude │
│ ▶  42      y = x * 2    x: 3    │        │
│    43      return y + 1         │        │
│──────────┬──────────┬───────────┤        │
│ Stack    │ Scope    │ REPL      │        │
│ (TAB ↻)  │ (TAB ↻)  │           │        │
└──────────┴──────────┴───────────┴────────┘
#+end_example

- In the editor, =●= in the fringe is a breakpoint, =▶= marks the line about
  to run, and the grey text after the current and previous lines shows the
  values of their variables.
- Each panel's header line lists its tabs; ~TAB~ / ~S-TAB~ cycle through them,
  or click one.  Left panel: Stack, Breakpoints, Threads, Modules, Sources.
  Middle panel: Scope, Watch.
-  Doom's debugger module puts dape's commands under ~SPC d~, and ~SPC o d~ also starts a session.  Each ~SPC d~ key also works as ~C-x C-a~ and the same letter; Run to Cursor has only ~C-x C-a u~.
- Not in dape: Smart Step Into, Mute Breakpoints, Force Step Into.

* A first session

1. Open a script and left-click the fringe next to a line inside a function
   or loop (or ~C-S-b~ on that line).
2. ~S-<f9>~.  The first time, type =debugpy= (~TAB~ completes) and ~RET~; it
   runs the current file.  Afterwards the prompt comes pre-filled with the
   last command.  To pass command-line arguments, add them before ~RET~:
   =debugpy :args ["--steps" "100"]=.  (=debugpy-module= runs the current
   directory as a package, like =python -m=.)
3. The program runs up to the breakpoint; Scope shows the local variables.
4. ~<f8>~ a few times to step over lines and watch the values change.
   ~<f7>~ on a function call steps into it; ~S-<f8>~ steps back out.
5. In Stack, move to a lower frame and ~RET~: the editor jumps to the caller
   and Scope shows the caller's variables.  Stepping always continues from
   the top frame.
6. ~<f9>~ continues to the next breakpoint.
7. ~S-<f5>~ quits: the panels close and the terminal comes back.  If the
   program finishes by itself, the REPL says "Session terminated"; ~S-<f5>~
   still closes the panels.

* The panels

| Panel       | Key       | What it does                                                    |
|-------------+-----------+-----------------------------------------------------------------|
| Stack       | ~RET~     | Select a frame: jump to its code and show its variables         |
| Breakpoints | ~RET~     | Go to the breakpoint; on the exception rows (raised / uncaught) |
|             |           | turn breaking on exceptions on or off                           |
|             | ~D~ / ~d~ | Disable a breakpoint / delete it                                |
|             | ~e~       | Edit a log breakpoint's message                                 |
| Scope       | ~e~       | Expand or collapse a dict, list or object                       |
|             | ~W~       | Add the variable to Watch                                       |
|             | ~=~       | Change the variable's value while paused                        |
| Watch       | ~W~       | Remove the expression from Watch                                |
|             | ~C-x C-q~ | Edit the list of watch expressions as text                      |

In Scope and Watch, ~RET~ does one of those three things depending on where
the cursor is: on the =+= / =-= it expands, on the name it adds to Watch, on
the value it edits.  To watch a variable straight from the code, put the
cursor on it and press ~SPC d w~.

* The REPL

- It shows everything the program prints.  The program can't read keyboard
  input (=input()=) in this setup.
- While paused, type any Python expression and it is evaluated in the
  selected frame: =len(sensors)=, =x * 2=, =vars(self)=.  Assignments such as
  ~x = 5~ work too.
- One-letter commands: =n= step over, =s= step into, =o= step out,
  =c= continue, =r= restart, =q= quit.  ~RET~ on an empty line repeats the
  last command, so =n= ~RET RET RET~ steps quickly.
- A variable named like a command (=b c d e k m n o p q r s t u w=) runs the
  command instead.  Type a space before the name to see the variable, as in " n".

* Breakpoints that don't just stop

- Conditional: middle-click the fringe (or ~SPC d e~) and enter a
  condition such as ~i == 50~.  The program stops only when it is true.
- Log: right-click the fringe (or ~SPC d l~) and enter a message such as
  ~step {i}: x={x}~.  The program doesn't stop; each hit prints the message
  in the REPL.  Expressions go in ={}=.
